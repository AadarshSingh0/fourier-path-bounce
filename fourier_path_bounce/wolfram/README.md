# Wolfram / FindBounce adapter

`FourierPathBounce.wl` is the generic boundary between Python-exported
Fourier path geometry and the external FindBounce solver.

It provides three public functions:

- `ImportFourierPathPoints[source, falseVacuum, trueVacuum]` imports and
  validates an open false-vacuum-to-true-vacuum path.
- `RunFindBounceWithFourier[potential, fields, falseVacuum, trueVacuum,
  dimension, source, options]` passes that path to the standard FindBounce
  calculation and returns its action, runtime, status, termination
  diagnostics, initial path, and solver object.
- `FindBounceTerminationReport[bounce, findBounceOptions, fieldCount]`
  classifies how any FindBounce calculation terminated, including one invoked
  directly rather than through the wrapper.

## Termination reporting

**A finite `Action` is not evidence of convergence.** FindBounce 1.1.0 runs its
path-deformation loop

```
While[iter <= maxItePath || switchPath,
  ...; If[switchPath || iter == maxItePath || bottomless, Break[]]; ...; iter++]
```

and sets `switchPath` when the relative path displacement drops below
`"PathTolerance"` or the relative action change drops below `"ActionTolerance"`.
The loop therefore exits either because a solver tolerance was met or because
the iteration cap was hit, and FindBounce does not report which. Every result
carries:

| Key | Meaning |
|---|---|
| `Status` | `ok`, `returned_at_path_iteration_limit`, `failed`, or `timeout` |
| `PathIterations` | iterations FindBounce actually performed (`bounce["PathIterations"]`) |
| `ConfiguredMaxPathIterations` | the effective cap, including FindBounce's own default (currently 3) when `"MaxPathIterations"` is not supplied |
| `PathIterationLimitReached` | `True` when the count reached the cap |
| `PathTolerance`, `ActionTolerance` | the tolerances that define the solver's stopping rule |
| `PathConvergence` | `solver_tolerance_satisfied`, `not_established_limit_reached`, `not_applicable_single_field`, or `unknown` |
| `ConvergenceEvidence` | prose statement of what those facts do and do not establish |

Interpretation:

- `PathIterations == ConfiguredMaxPathIterations` is **ambiguous**. The action
  may be truncated, or the tolerance may have been met at exactly that
  iteration. Rerun with a larger cap and compare the actions to tell them apart.
- `PathIterations < ConfiguredMaxPathIterations` means FindBounce's own stopping
  rule fired. That is **not** a proof of numerical convergence; the default
  `"PathTolerance"` of 0.01 is a 1% path-displacement criterion. Confirm by
  varying the tolerances, the cap, and the number of field points.
- For a single field FindBounce performs no path deformation at all, so the
  limit does not apply.

The action, the imported initial path, and the `BounceFunction` are always
returned, so a limit-reached or failed run remains fully diagnosable. Results
written with `"ResultFile"` are JSON-encodable in every status.

Mathematica or Wolfram Engine and an installed FindBounce package are required.
They are external dependencies and are not bundled with this repository.

## Workflow

1. Optimize and export the Fourier path in Python.
2. Define the potential, fields, vacua, and optional gradient in Wolfram.
3. Load `FourierPathBounce.wl`.
4. Call `RunFindBounceWithFourier`; FindBounce performs the final bounce
   calculation.

Run `python3 -m examples.reusable_findbounce_example` first, then the
following from the repository root:

```wolfram
Get[FileNameJoin[{
  Directory[], "fourier_path_bounce", "wolfram", "FourierPathBounce.wl"
}]];

fields = {x, y};
potential = 1/4 (x^2 - 1)^2 +
  1/2 (y - 0.35 (x^2 - 1))^2 - 0.1 x;
gradient = {D[potential, x], D[potential, y]};
falseVacuum = {-0.9456492739235919, -0.03701160775472421};
trueVacuum = {1.0466805318046022, 0.033439047480567696};
metadataFile = FileNameJoin[{
  Directory[], "example_output", "findbounce_K4",
  "initializer_metadata.json"
}];

result = FourierPathBounce`RunFindBounceWithFourier[
  potential, fields, falseVacuum, trueVacuum, 4, metadataFile,
  "Gradient" -> gradient,
  "FindBounceOptions" -> {"MaxPathIterations" -> 20, "PathTolerance" -> 0.01},
  "TimeLimit" -> 120
];
Print[KeyDrop[result, {"Bounce", "InitialPath"}]];
```

Always inspect `Status`, `PathIterations`, `ConfiguredMaxPathIterations` and
`ConvergenceEvidence` before quoting an action. Note that the K=4 case of this
example needs `"MaxPathIterations" -> 20`; with the FindBounce default of 3, or
with 10, it stops at the limit and its action is not established.

The source may be an explicit numeric point matrix, a full-path CSV file, or
the metadata JSON generated by the Python exporter. In every case the path
must be open and ordered from false vacuum to true vacuum.

for geometry export and
